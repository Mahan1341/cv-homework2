# ДЗ 2: сканер документов

В проекте — реализованный сканер, тесты, проверка на данных курса и скрипты
для обработки собственного набора. Для полной сдачи ещё нужны **18 своих
фотографий**, разметка и **видео со своей камеры**. Изображения `sample_data/`
синтетические и не заменяют личный набор.

## 1. Запуск

Откройте терминал в распакованной папке, где лежит `docscan.py`.
Можно использовать уже установленное окружение курса. Новое окружение в PowerShell:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest tests -q
```

Подойдёт и Python 3.10. Далее `python` означает интерпретатор этого окружения:
активируйте его или заменяйте `python` на `.\.venv\Scripts\python.exe`.

Пример — скан листа с закрытым углом:

```powershell
python docscan.py scan sample_data/corner.jpg --canny 50,150 -o out/demo_scan.jpg --bw out/demo_bw.png
```

Повторить полный прогон курса:

```powershell
python run_experiments.py --data sample_data --out out/course
```

В `out/course/` уже включены измеренные результаты: `RESULTS.md`, исходные
JSON-логи, команды, CSV, карты краёв, сканы и рамки обнаружения.
`REPORT.md` объясняет эти измерения; `EXPLAIN.md` помогает разобраться в коде.

## 2. Свои фотографии

План всех 18 кадров — в `data/README.md`. Скопируйте 18 исходных JPG/JPEG/PNG
в папку `raw/`. Удобно заранее назвать их `01.jpg` … `18.jpg` по плану.

```powershell
python prepare_data.py raw --out data
python docscan.py annotate data --ann data/corners.json
```

Первый скрипт уменьшает длинную сторону до 2000 пикселей, каждый JPEG — до
размера меньше 1 МБ. Исходники сохраняются; соответствие имён записывается
в `data/source_files.json`. Если в `data/` уже есть фото или разметка,
скрипт попросит выбрать другую папку, чтобы не затереть готовую работу.
Разметку нужно делать после уменьшения, на уже подготовленных фотографиях.

В окне разметки:

- Четыре клика по углам листа в произвольном порядке → **Enter**.
- Закрытый предметом угол: отметить предполагаемое положение угла.
- **r** — сбросить клики текущего кадра.
- **n** — один из трёх запланированных негативных кадров.

Обычный положительный кадр не становится негативным из-за ошибки программы.
Разметка сохраняется после каждого снимка. Исправить один кадр:

```powershell
python docscan.py annotate data/07.jpg --ann data/corners.json --redo
```

## 3. Все измерения на своём наборе

```powershell
python run_experiments.py --data data --out out/personal --personal
```

Скрипт проверяет имена, размеры, разрешение, полную разметку и соотношение
15 положительных / 3 негативных. Затем оценивает шум, строит карты краёв,
делает три прогона `eval` с 20 зёрнами RANSAC и сравнивает бинаризацию.
Реальные отказы сохраняются в результатах.

Таблицы будут в `out/personal/RESULTS.md`; `REPORT.md` не перезаписывается.
Изображения и измерения в исходном `REPORT.md` относятся к курсу, поэтому
после съёмки нужно добавить собственные таблицы и выводы по своим кадрам.

Общая настройка, выбранная по учебному набору:

```text
--canny 50,150 --close 9 --long-side 640
```

Сравните её с медианными порогами на всём своём наборе. Не выбирайте
разные параметры по известной разметке отдельно для каждого снимка.

## 4. Камера

Запускайте локально. Во время записи двигайте лист, прикройте угол ладонью,
затем уберите лист. Номер камеры обычно `0`; при необходимости попробуйте `1`.

```powershell
python docscan.py video --source 0 --method contour --canny 50,150 --seconds 10
python docscan.py video --source 0 --method hough --canny 50,150 --seconds 10
python docscan.py video --source 0 --method auto --canny 50,150 --seconds 10 --save out/video.mp4
```

Перенесите три JSON-строки в отчёт, укажите CPU и `frame_size` камеры.
Требование к `auto`: не менее 10 FPS на вашем компьютере. Если медленно,
попробуйте `--long-side 480` и заново сравните режимы с одной настройкой.
`fps` относится к циклу обработки; `finalize_seconds` — к отдельному
сохранению ролика после захвата. Для камеры частота записи согласуется
с измеренной длительностью. Реальная камера в серверной проверке не использовалась.

Проверьте размер ролика: не больше 10 МБ. При необходимости уменьшите
разрешение самой камеры. `--long-side` уменьшает кадр для поиска,
но не разрешение сохраняемого видео.

## 5. Перед сдачей

1. В `data/` — 18 собственных фотографий и `corners.json`.
2. В `REPORT.md` — ваши числа, условия съёмки, три негативных случая,
   хотя бы один неудачный положительный кадр и причины отказов.
3. В сравнении путей — минимум два примера преимущества каждого,
   с соответствующими картами краёв.
4. Указаны одна общая настройка, команды, инструменты и использование ИИ.
5. В `out/` — результаты на своих снимках и запись камеры.
6. Тесты проходят. После загрузки в **свой GitHub Classroom** проверьте Actions:
   локальная проверка не подтверждает состояние удалённого CI.

Копируйте файлы в корень Classroom-репозитория: `docscan.py`, `requirements.txt`,
`REPORT.md`, `data/`, `out/`, `tests/`, `.github/workflows/` и используемые
скрипты воспроизведения. Не загружайте `.venv`, `raw` и кэши Python/pytest.
